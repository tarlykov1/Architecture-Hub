# Architecture Hub – общие сценарии обмена данными

Дата: 21.11.2026. Реализация: [PR #214](https://github.com/tarlykov1/Architecture-Hub/pull/214).

## Назначение

**Технический поток** (объект `data_flows`) – направленная запись передачи данных между существующими компонентами. У него один ID, источник, получатель, порт и прочие характеристики.

**Сценарий обмена** – именованная, совместно используемая последовательность ссылок на такие потоки. Один и тот же поток может повторяться в сценарии, например при повторном запросе. Сценарии связываются с бизнес-процессом, но не создают отдельную копию технического потока.

Диаграмма последовательности – представление сценария. Стрелки на ней **не доказывают** реально наблюдаемую сетевую активность.

## Модель данных

| Объект | Поля | Назначение |
|---|---|---|
| `flow_scenarios` | UUID, name, description, process_id (optional), revision, created_at, updated_at | Сценарий и его актуальная версия |
| `flow_scenario_steps` | UUID, scenario_id, flow_id, position, reply, note | Отдельный шаг и ссылка на один реальный поток |
| `data_flows` | Existing canonical flow ID | Источник истины о техническом обмене |
| `business_processes` | Existing canonical process ID | Бизнес-контекст |

Индивидуальные ID шагов стабильны при перестановке. Повторяющиеся `flow_id` разрешены. `position` задаёт порядок, `reply` меняет только обозначение шага (пунктир), не направление зарегистрированного технического потока.

## API и права

- `GET /api/flow-scenarios`, `GET /api/flow-scenarios/{id}` – список и карточка, доступ по действующим правам на потоки.
- `POST /api/flow-scenarios` – создать сценарий, список шагов и связь с БП.
- `PUT /api/flow-scenarios/{id}` – сохранить новый порядок, описание, название, заметки и связь с БП с обязательным `expected_revision`.
- `DELETE /api/flow-scenarios/{id}` – удалить сценарий, сохранив все технические потоки.

API отклоняет неизвестные `flow_id`, отсутствующий `process_id`, повторные ID шагов, конфликт имён, устаревшую ревизию. Удаление технического потока, на который ссылается любой сценарий, возвращает 409 – сначала нужно убрать соответствующие шаги. Изменение сценария журналируется как одна атомарная ревизия.

RBAC тот же, что у технических потоков: просмотр и редактирование по существующему разделению ролей. Anonymous/demonstration не получает доступ к серверному реестру без разрешения.

## UX

Открыть **Обзор → Потоки данных → Последовательность**. Появляется выбор «Общая последовательность (локально)» либо существующего общего сценария.

- Локальный режим остаётся прежним: пользовательский порядок сохраняется только в данном браузере.
- «Сохранить как сценарий» создаёт совместно используемый объект на основе **видимых** потоков; можно задать БП.
- При редактировании можно добавить поток повторно, изменить последовательность, пометку ответа, примечание шага, название, описание и БП.
- «Сохранить сценарий» отправляет пакет одной операцией. «Отменить изменения» возвращает к последней серверной ревизии.
- Если другой сотрудник внёс правки раньше, сервер отвечает 409; это не автоматическое объединение конфликтующих правок.
- Фильтр систем скрывает шаги вне выбранного контекста, но не удаляет их из записанного сценария. Недоступные ссылки явно помечаются.

## Инварианты и тесты

1. Один `flow_id` может присутствовать в нескольких сценариях и повторяться внутри одного.
2. Сохранение порядка не меняет ID, направление, порт или защиту технического потока.
3. Удаление сценария не удаляет ИС/ВМ/потоки.
4. Нельзя удалить реальный поток, если его использует сценарий.
5. БП выбирается по существующей записи, не копируется в сценарий.
6. Сохранение после устаревшей ревизии возвращает 409 и не перезаписывает чужой результат.

Проверки: `backend/tests/test_flow_scenarios.py`, `backend/tests/test_flow_scenario_migration.py`, `frontend/e2e/flow-scenarios.spec.ts`, существующий `flow-sequence.spec.ts`.

## Что пока отложено

Сценарии как часть технического решения, отдельные стадии согласования сценария, условия ветвления, BPMN-исполнитель, полноценная история редакций и импорт из трассировок. Они требуют самостоятельного проектирования; текущая последовательность – декларативная архитектурная документация, а не система оркестрации процессов.
