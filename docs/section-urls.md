# Прямые ссылки и навигация Architecture Hub

Новая клиентская навигация использует History API и самостоятельные URL разделов:

| Раздел | URL |
|---|---|
| Обзор | `/` |
| Системы | `/systems` |
| Компоненты | `/components` |
| Потоки | `/flows` |
| Бизнес-процессы | `/business` |
| Реестр сетей | `/networks` |
| Топология сетей | `/topology` |
| Инциденты | `/incidents` |
| Wiki.js · База знаний | `/knowledge` |

В компонентах и потоках конкретная ИС передаётся через параметр `?system=<uuid>`.
Пример: `/components?system=9f76e893-c478-44b4-9f0f-5f812e16696a`.

Переход между разделами не перезагружает страницу. Обновление, «Назад», «Вперёд»
и открытие URL в новой вкладке должны сохранять раздел и выбранную ИС.
Ключ доступа к API остаётся только в sessionStorage текущей вкладки;
URL не содержит ключей или токенов.

## ВАЖНО: настройка веб-сервера для прямых ссылок

Прямой запрос на `/components`, `/flows` и другие разделы должен
возвращать frontend `index.html` (а не 404). В конфигурации Nginx,
обслуживающей собранный SPA frontend, необходим fallback:

```nginx
location / {
    try_files $uri $uri/ /index.html;
}

location /api/ {
    # Сохранить существующий proxy_pass и параметры безопасности для FastAPI.
    proxy_pass http://127.0.0.1:8001;
}
```

Настройку `location /api/` здесь приводим **только как иллюстрацию**;
реальный адрес/порт upstream необходимо взять из действующей конфигурации.
Не заменяйте существующий блок `/api/`, если в нём уже настроены права,
заголовки и HTTPS. Изменения серверной конфигурации и деплой выполняются
отдельно, после проверки frontend-ветки.

Vite dev-сервер автоматически возвращает `index.html` для History API,
поэтому браузерные тесты в CI могут проходить, даже если Nginx ещё
не настроен на прямые URL. Проверить продакшен после деплоя:
`curl -I https://test.web-tie.ru/components` и открыть этот адрес в чистой вкладке.
