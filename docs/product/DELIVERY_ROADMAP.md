# ArchHub: дорожная карта превращения MVP в архитектурную платформу

Статус: **предлагаемый план разработки**; сроки и оценки после технического grooming. [Цель](ARCHITECTURE_VISION.md) · [Метамодель](METAMODEL_V1.md).

## Приоритеты

- **P0** — отсутствие этого свойства делает дальнейшие изменения ненадёжными/опасными.
- **P1** — основа полезного архитектурного продукта.
- **P2** — функции, улучшающие качество решений и ценность для подразделений.
- **P3** — расширения после эксплуатации и доказанного спроса.

Мы не стремимся повторить все функции Ardoq, IcePanel, LeanIX и NetBox. Берём от них лучшие рабочие принципы и внедряем через проверяемые сценарии.

## Этап 0 — устойчивый фундамент (P0)

| ID | Задача | Результат и критерий приёмки |
|---|---|---|
| AH-PLAT-001 | Синхронизация фронтенд/backend по версии и миграциям | UI не показывает функции без поддерживаемого API; build hash и backend schema revision доступны администратору |
| AH-PLAT-002 | Предсказуемые CI/CD | TypeScript, Python, Playwright и миграции проходят; нет деплоя при неуспешном CI; rollback при несовместимой сборке |
| AH-PLAT-003 | Резервирование, dry-run миграций, восстановление | Restore-тест SQLite на отдельной копии; сохранённые объекты не теряют ID |
| AH-PLAT-004 | Договор об ошибках API и guest/read-only | 401/403/404/409/422 понятны пользователю, UI не падает, demo не выдаёт реальные данные |
| AH-PLAT-005 | Репозиторий и актуальный README | README не утверждает, что нет логина и миграций; есть ссылки на архитектурный контракт, статус возможностей и ограничения |
| AH-PLAT-006 | Закрытие критичных UX регрессий | редактор контейнеров, перенос концов потоков, сохранение, история, мобильный dock, Escape/keyboard проходят пользовательские сценарии |

**Gate 0:** на тестовом стенде подтверждён номер ревизии UI/API и полный smoke QA. Не смешивать разработку кода и ручное развёртывание; деплой выполняется отдельной процедурой с backup.

## Этап 6 — интеграции и промышленная эксплуатация (P2/P3)

Коннекторы ITSM/CMDB, каталогов, виртуализации, NetBox/IPAM, Grafana, GitHub и Wiki.js через устойчивый import API. Для каждого источника: idempotency, incremental sync, reconciliation, visibility, rate limits, секреты только в secure storage, job history и отчёт об ошибках. Отдельный data-ingestion worker перед масштабированием; не превращать FastAPI в неконтролируемый scheduler.

Интеграции подключаются после утверждения канонической модели, иначе они будут размножать дубли.

## Оптимальная последовательность первой волны

1. **P0:** выровнять сборку/стенд, устранить проблемы сохранения и UX, согласовать метамодель.
2. **P1:** уникальные идентификаторы, связи/источники, отдельные viewpoints и editable regions.
3. **P1:** интеграционные потоки + разные наборы атрибутов по процессам.
4. **P1:** нормализация VRF/VLAN/NIC/Prefix и паспорт IS/VM.
5. **P2:** quality/governance, impact analysis, будущая архитектура.
6. **P3:** коннекторы, импорты и сложная аналитика.

## Product KPI (предлагаемые метрики, не фактические результаты)

| Метрика | Как считаем | Пилотный ориентир |
|---|---|---|
| Time to trace | Найти IS → flow → target VM/NIC/zone | ≤ 3 мин при наличии данных |
| Cross-view consistency | Один object ID / relationship при переключении видов | 100% |
| Verified critical relations | Verified / relevant critical relations | ≥ 80% в пилотном контуре |
| Unexplained impact | Доля выводов без traceable path | 0 |
| Data completeness | Весовой % обязательных полей | ≥ 85% для пилотных ИС |
| Unsafe edit | Отредактированная рамка поменяла инфраструктурный факт | 0 |
| Browser critical regressions | P0/P1 на согласованных сценариях | 0 до релиза |
| Change audit completeness | Изменение имеет actor, timestamp, reason, before/after | 100% |

Ориентиры требуют утверждения владельцами продукта и пилотной замерки, не следует выдавать их за SLA.

## Definition of Done для любой новой функции

- Сформулирован вопрос пользователя и перечень затронутых типов данных.
- Договорённость о семантике документирована в метамодели.
- API валидирует типы, права, состояние и конфликтную запись.
- Нет скрытого изменения source of truth из-за взаимодействия с визуализацией.
- Есть тесты API + Playwright с позитивным, негативным и гостевым сценариями.
- Нет потери ID и существующих данных; миграция аддитивная, проверена backup/restore.
- UX проверен для desktop/mobile, keyboard/Escape/zoom/fit, ошибок и пустых состояний.
- Документация, версия и реальный smoke после деплоя подтверждены.
- CI зелёный до merge; способ отката известен.

## Что НЕ делать сейчас

- Переписывать всё на Neo4j/другой графовый движок без подтверждённой потребности.
- Усложнять интерфейс десятками классов ArchiMate без пользовательского сценария.
- Создавать новую схему для каждой перспективы с собственными объектами.
- Внедрять автоматическое обнаружение инфраструктуры до нормализации источников.
- Считать пройденный TypeScript build доказательством пользовательской работоспособности.
