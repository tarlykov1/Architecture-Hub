# Architecture Hub: аудит и доработка рабочего пространства

Дата: 3 ноября 2026. Ветка: `feature/ux-cleanup`. База: `main` / `2f68ec336e9f7898e5331b2ca0762bb288629ad6`.

## Границы проверки

Рабочее приложение `https://test.web-tie.ru/` открыто в Cloud Browser. Сервер API вернул `Authentication required`; данные и реальные производственные сценарии без входа недоступны. Это ограничение не выдаётся за успешную проверку живых данных.

Все восемь разделов повторно проверены в Chromium на локальной копии актуальной main и доработанной ветки. Использована отдельная SQLite-база с синтетическими данными: 8 ИС, 30 компонентов, 14 потоков, 9 сетевых групп, бизнес-процессы. Скриншоты сняты до запуска изменяющих данные тестов, в одинаковом окне 1440×1000. Реальные записи и настройки сервера не изменялись. Backend и API-контракты не менялись.

## Переносы и устранённые дублирования

- С обзора убраны постоянные фильтры контура и ИС: они находятся в «Фильтры и слои».
- Из потоков в «Настройки потоков и качество данных» перенесены подбор компонента, группировка, расположение, расстояния, обзор по ИС, экспорт CSV и аудит характеристик. Направление/глубина показываются для выбранного компонента.
- В топологии VRF/VLAN, контур и тип связей находятся в «Фильтры топологии»; параметры отображения и выбора потока – в «Отображение и направления».
- Проверка полноты компонентов доступна через «Качество данных».
- Убрано одновременное отображение схемы, таблицы и карточек одних компонентов.
- Убрана повторная кнопка редактирования в раскрытой карточке потока.
- Убраны версия продукта и повторный заголовок топологии, повторный заголовок ИТ-ландшафта и постоянный поясняющий блок межсистемных потоков.
- Существующее меню создания/импорта сохранено; исправлено закрытие после действия, по Escape и клику снаружи.

## Что осталось

1. Авторизованная проверка `test.web-tie.ru` на фактической модели. Изменения в этой ветке не развёрнуты на сервере, поэтому живой сайт продолжает показывать main.
2. Нагрузочная UX-проверка схем на сотнях/тысячах компонентов и реальных сложных сетевых привязках. Снимки и тесты не доказывают читаемость произвольной большой модели; для неё потребуются агрегирование и дополнительные уровни детализации.
3. Глобальный обзор сетей отображает зарегистрированные логические связи, а не физическую трассировку. Подписи всех узлов большой модели невозможно держать читаемыми в одном масштабе; доступны фокус на ИС и просмотр зависимостей.
4. В реестре компонентов сохранена широкая техническая таблица с собственной горизонтальной прокруткой. Документ не переполняется, но настройка видимых колонок – отдельная доработка.
5. Production build сообщает о JS-чанке больше 500 kB. Динамическое разделение разделов на чанки можно выполнить отдельно.
6. Поиск по рабочему разделу и сохранённые представления сохранены. Полное сохранение независимого рабочего состояния каждого раздела и предупреждения о несохранённых формах требуют отдельного проектирования.

Слияние в main и развёртывание не выполнялись.
